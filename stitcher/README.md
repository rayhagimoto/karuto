# Appshot stitching library

The Rust library aligns overlapping BGRA screenshots into one vertical PNG. Swift owns the capture session and borrows frame bytes synchronously through `Sources/CStitcher/include/KarutoStitcher.h`. `StitchingSession` serializes append, finish and cancellation.

Build with `cargo build --release --manifest-path stitcher/Cargo.toml`; run `cargo test --manifest-path stitcher/Cargo.toml`. Link the static archive with the macOS system `z` library. No crates, browser component, network client or extra runtime are required.

The processor samples luminance to find a unique forward offset, verifies that match against color pixels and rejects ambiguous results. It keeps the last accepted frame plus bounded sampling data. Accepted rows are appended to a scratch file; final PNG encoding reads one row at a time and uses incremental system-zlib compression. Publication uses a temporary file and a same-directory hard link to avoid overwriting existing output. Cancellation removes only the library-owned scratch file.

`sx_stitcher_create_calibrated` enables motion-verified viewport discovery. It retains four distinct input frames, proposes moving bounds using majority evidence across three pairs, and requires stationary contrast before excluding an outer band. All three cropped pairs must pass the existing strict displacement matcher. Retained samples are replayed before the crop is published by `sx_stitcher_content_rect`, preserving the start of the content. Disposition 4 means calibration is pending; 2 means alignment could not be verified. No unverified full-frame result is returned. Calibration adds at most four decoded frames (128 MiB under the existing 32 MiB per-frame cap), released after successful verification or rejection; this is active-capture memory, not idle memory.

The alpha accepts a downward, fixed-size region 16–4096 pixels wide, at least 32 pixels tall, at most 32 MiB decoded per frame. Output is capped at 100 million pixels and capture duration at two minutes. Include overlapping content when scrolling. Uniform/repeated content, persistent headers and animation may require a smaller region or reconnection. Those cases are rejected conservatively; arbitrary document layout reconstruction is not implemented.

Tests verify synthetic alignment, padded row strides, reverse and duplicate frames, repeated-content rejection, nonoverlap and sticky-header rejection, invalid input, limits, cleanup, and complete PNG output decoded through zlib with independently checked chunk checksums. Calibration tests cover exact four-edge exclusion and initial-frame replay, duplicates, majority evidence with low-contrast patterns, blank/repeated/animated content, independently moving panes, and the C interface. Swift integration tests additionally decode the PNG using Apple's Image I/O. Live capture behavior must be verified in the application.
